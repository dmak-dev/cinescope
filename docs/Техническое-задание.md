# Техническое задание на приложение для поиска фильмов

## 1. Общие сведения

1.1. Наименование разработки: приложение для поиска фильмов, рабочее название CineScope.

1.2. Основание для разработки: ____.

1.3. Заказчик: ____. Исполнитель: ____.

1.4. Сроки начала и окончания работ: ____.

## 2. Назначение разработки

2.1. Приложение предназначено для получения справочных сведений о фильме по его названию. Пользователь вводит название в браузере и получает карточку с годом выпуска, рейтингом IMDb, жанром, режиссёром, актёрами, постером и описанием сюжета.

2.2. Источник сведений - внешний сервис OMDb, доступный по протоколу HTTP. Собственная база фильмов не создаётся, хранение данных между запросами не предусмотрено.

2.3. Приложение рассчитано на одного пользователя, работающего в браузере настольного компьютера. Аутентификация и разграничение прав доступа не требуются.

## 3. Требования к серверной части

3.1. Сервер реализуется на Node.js с использованием фреймворка Express.

3.2. Сервер принимает запрос клиента методом GET по адресу /api/movie и передаёт его внешнему сервису OMDb.

3.3. Обязательный параметр запроса title содержит название фильма на английском языке. Необязательный параметр year содержит год выпуска в виде четырёх цифр и передаётся внешнему сервису для уточнения выбора, когда одно и то же название носят несколько фильмов.

3.4. Название проверяется после удаления пробелов по краям. Запрос без параметра title и запрос, в котором название состоит из одних пробелов, отклоняются с кодом 400.

3.5. Год, не соответствующий шаблону из четырёх цифр, отклоняется с кодом 400 до обращения к внешнему сервису.

3.6. Обращение к OMDb выполняется с таймаутом 8 секунд. Ключ доступа берётся из переменной окружения OMDB_API_KEY.

3.7. Отсутствие ключа доступа при запуске приводит к отказу старта сервера с диагностическим сообщением в консоли.

3.8. Сервер отдаёт статические файлы собранного клиента при наличии каталога сборки. Благодаря этому приложение поднимается одной командой на одном порту и не требует отдельного веб-сервера.

3.9. Порт сервера задаётся переменной окружения PORT, значение по умолчанию 3000.

## 4. Требования к клиентской части

4.1. Клиент реализуется на Vue 3 со сборщиком Vite.

4.2. Форма поиска содержит поле названия фильма, необязательное поле года и кнопки поиска и очистки. Поле названия обязательно для заполнения.

4.3. Отправка формы и вывод результата происходят без перезагрузки страницы.

4.4. На время запроса выводится признак загрузки, кнопка поиска блокируется.

4.5. Результат выводится карточкой: постер, название с годом выпуска, рейтинг IMDb, жанр, режиссёр, актёры, описание сюжета, время получения данных.

4.6. Значения, отсутствующие во внешнем сервисе (строка N/A), выводятся прочерком.

4.7. Кнопка очистки сбрасывает форму и ранее выведенный результат.

4.8. Адрес API задаётся на этапе сборки переменной VITE_API_URL. Значение по умолчанию - http://localhost:3000.

4.9. Оформление рассчитано на тёмную тему и не зависит от темы оформления операционной системы: при светлой теме системы текст остаётся читаемым.

4.10. Интерфейс на русском языке, тексты сообщений об ошибках также на русском.

## 5. Требования к структуре данных

5.1. Ответ сервера на успешный запрос содержит поля title, year, plot, poster, imdbRating, genre, director, actors, timestamp.

5.2. Поля title и year содержат название и год выпуска фильма. Поле plot содержит описание сюжета, поле poster - адрес постера, поле imdbRating - рейтинг IMDb.

5.3. Поля genre, director и actors содержат жанр, режиссёра и список актёров строкой.

5.4. Поле timestamp содержит время формирования ответа сервером в формате ISO 8601.

5.5. Ответ на ошибочный запрос содержит единственное поле error с текстом на русском языке.

## 6. Требования к обработке ошибок

6.1. Код 400 возвращается при отсутствии названия фильма и при некорректно указанном годе.

6.2. Код 404 возвращается, когда фильм не найден во внешнем сервисе.

6.3. Код 502 возвращается при отклонённом ключе доступа и при прочих ошибках внешнего сервиса.

6.4. Код 504 возвращается, когда внешний сервис не ответил в течение 8 секунд.

6.5. Тексты ошибок внешнего сервиса приводятся к фиксированному набору русских формулировок: «Фильм не найден», «Введите название фильма», «Неверный ключ API OMDb», «Исчерпан дневной лимит запросов к OMDb».

6.6. При недоступности сервера клиент выводит сообщение «Нет связи с сервером» вместо пустого экрана.

## 7. Требования к документированию

7.1. В состав поставки входит README.md с описанием стека, порядка установки и запуска, переменных окружения, контракта API и порядка прогона проверок.

7.2. В состав поставки входит настоящее техническое задание.

7.3. Проект распространяется по лицензии MIT.

## 8. Порядок контроля и приёмки

8.1. Контракт HTTP-интерфейса проверяется набором автоматических проверок, запускаемых командой npm test в каталоге backend.

8.2. Проверками подтверждается отклонение запроса без названия фильма, отклонение названия из одних пробелов, отклонение года, не состоящего из четырёх цифр, структура карточки успешного ответа, уточнение выбора фильма по году, текст ошибки для ненайденного фильма.

8.3. Проверки обращаются к внешнему сервису OMDb, поэтому для их прогона требуются действующий ключ доступа и доступ в сеть.

8.4. Готовность клиентской части подтверждается успешной сборкой командой npm run build в каталоге frontend.

## 9. Требования к развёртыванию

9.1. Требуется Node.js версии 20.19 или новее.

9.2. Требуется ключ доступа к OMDb API. Ключ выдаётся сервисом бесплатно и подставляется в файл .env на основе .env.example.

9.3. Файл .env с ключом в репозиторий не включается.

9.4. Запуск приложения в режиме разработки требует двух процессов: сервер и сервер разработки клиента. Запуск собранного приложения требует одного процесса сервера.

## 10. Направления развития

10.1. Поиск по русскому названию: база OMDb содержит только английские названия, поэтому запрос вида «Матрица» завершается ошибкой. Требуется перевод запроса либо дополнительный источник данных.

10.2. Список избранных фильмов и история последних запросов с сохранением в браузере.

10.3. Кеширование ответов внешнего сервиса для повторных запросов.

10.4. Кнопка повторного запроса для обновления сведений о текущем фильме.

10.5. Подробная карточка фильма: рейтинги дополнительных источников, длительность, страна, награды.
